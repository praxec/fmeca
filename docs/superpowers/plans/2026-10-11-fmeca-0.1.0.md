# fmeca 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks marked **[Junior]** are executed with the `junior` skill (`junior handoff`), not by a Claude subagent; tasks marked **[Controller]** are run by the orchestrating session and need the maintainer's explicit go-ahead at the time.

**Goal:** Release fmeca 0.1.0, with the repository ready for open source, the `fmeca-*` agent skills and `skills install`, an npm launcher, and an advisory `vet` tool (Jev via OpenRouter), without changing anything in the Junior contract.

**Architecture:** There are 14 tickets (#13–#26), each delivered on its own feature branch from `origin/dev` and merged by PR into `dev`. The kernel crate `fmeca` stays pure. All new runtime behaviour lives in `fmeca-mcp`: the CLI subcommands, `skills.rs`, and `jev/` + `vet.rs` behind the default cargo feature `jev`. The repo pieces we share with cpm-planner (the skills installer, the npm launcher, CI, the Jev client) are **ported** from cpm-planner `origin/main` (`1fdd3af`, v0.2.2) and adapted. They are not extracted into a shared crate.

**Tech Stack:**
- Rust 1.99.0 (edition 2024, MSRV 1.85), rmcp 1.8, tokio
- `rig-core` / `rig-typesafeai` / `rig-reqwest` 0.44 (rustls), `async-trait`, `sha2`
- `wiremock` 0.6 (dev), `serde_yaml_ng` (dev)
- GitHub Actions, cargo-deny
- Node ≥ 18 for the npm launcher, `node:test`

**Spec:** `docs/superpowers/specs/2026-10-11-fmeca-0.1.0-design.md`. Its section 1 lists where the observed repo state differs from the epic text, so read it first. Binding source: epic praxec/fmeca#12.

## Global Constraints

- **Junior contract (frozen):**
  - repo `praxec/fmeca`;
  - binary `fmeca-mcp` (`fmeca-mcp.exe` on Windows);
  - archives `fmeca-mcp-{x86_64-unknown-linux-gnu,aarch64-unknown-linux-gnu,x86_64-apple-darwin,aarch64-apple-darwin}.tar.gz` and `fmeca-mcp-{x86_64-pc-windows-msvc,aarch64-pc-windows-msvc}.zip`;
  - release asset `checksums.sha256` with `<hex>  <name>` lines covering every archive;
  - MCP tools `session.open`, `append`, `state.get`, `risk.next`, `readiness.assess`, `report.export`, `scoring.catalog`, `analyze`, with compatible inputs and outputs.

  New tools and flags are additions only.
- **Branches:** every branch starts from `origin/dev`. Feature PRs go into `dev`; the release PR goes `dev → main` (merge commit); the tag `v0.1.0` goes on `main`.
- **Version:** 0.1.0, synced across workspace `Cargo.toml`, the `fmeca` dep in `crates/fmeca-mcp/Cargo.toml`, `Cargo.lock`, `server.json` (top-level `version` + OCI identifier tag; no OCI `version` field), and `npm/package.json`.
- **Kernel:** `crates/fmeca` gains no dependency (dev-dependencies are allowed) and no network access. `cargo tree -p fmeca -e normal` contains no `rig` or `reqwest`.
- **Jev is advisory:**
  - `vet` never appends to the log;
  - it never changes `state.get`, `risk.next`, `readiness.assess` or `report.export`;
  - failures return `{status:"vet_unavailable", reason}` with `isError:false`.
- **Jev config (environment only):**
  - `OPENROUTER_API_KEY`;
  - `FMECA_JEV_MODEL` (default `typesafe/jev-1.13`);
  - `FMECA_JEV_TIMEOUT_SECS` (default 30, range 1..=300);
  - endpoint `https://openrouter.ai/api/v1/systemone`.

  There is no key file, and the key is never logged, echoed or written to a file.
- **Project store:** the state dir resolves in this order: `FMECA_STATE_DIR` → the nearest ancestor `.fmeca/` → the user default → `./fmeca-state`. Logs stay flat `<session_id>.jsonl` and append-only. Every new event or field is optional with a serde default, so old logs replay unchanged. The kernel never reads a clock: the server stamps `at`.
- **No-arg behaviour:** `fmeca-mcp` with no arguments runs the stdio MCP server exactly as today. Nothing may be written to stdout before the MCP transport starts.
- **Gates for every PR:** `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` (locally), `cargo test --workspace` (Linux, macOS, Windows in CI), plus the jobs this plan adds.
- **Tests:** declarative names, one behavioural assertion each, no network in default tests. Live tests are `#[ignore]` and need `OPENROUTER_API_KEY`.
- **Ports:** read cpm-planner sources with `git -C ../cpm-planner show origin/main:<path>`. The `../cpm-planner` working tree is on a stale branch, so never copy from it.
- **Commits:** conventional commits. End each commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, and end each PR body with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. PR bodies say `Part of #12` and `Closes #N`.

## Review Focus

1. **A `vet` run on a session the agent then keeps editing.** The expected behaviour is that `vet` reads one consistent snapshot, the log length is unchanged afterwards, and a later `append` works. *Test:* Task 7 `vet_leaves_session_outputs_byte_identical`.

4. **`skills install` run twice after the user edited a generated `SKILL.md`.** The expected behaviour is that the edit is kept, the file is reported "modified, skipped", and the exit code is 0. *Test:* Task 9 (ported) `user_edited_file_is_skipped`.
5. **Two branches each append to the same `.fmeca/<id>.jsonl` and are merged.** Union merge keeps both sides, so the same failure-mode id can be added twice. `repo_hygiene.rs` is a port of cpm-planner's `tests/repo_hygiene.rs::tracked_text_files_are_lf`, with one difference: it runs `git ls-files` from the **workspace root**, which is `CARGO_MANIFEST_DIR/../..`.

```rust
use std::path::{Path, PathBuf};
use std::process::Command;

const BINARY_EXTENSIONS: &[&str] = &["png", "ico", "jpg", "gif", "db", "sqlite", "zip", "gz", "tgz"];

fn workspace_root() -> PathBuf {
    Path::new(env!("CARGO_MANIFEST_DIR")).join("../..")
}

fn is_binary_path(path: &str) -> bool {
    Path::new(path)
        .extension()
        .and_then(|ext| ext.to_str())
        .is_some_and(|ext| BINARY_EXTENSIONS.iter().any(|b| ext.eq_ignore_ascii_case(b)))
}

fn contains_crlf(path: &Path) -> bool {
    std::fs::read(path).is_ok_and(|bytes| bytes.windows(2).any(|w| w == b"\r\n"))
}

#[test]
fn tracked_text_files_are_lf() {
    let root = workspace_root();
    let output = match Command::new("git").args(["ls-files", "-z"]).current_dir(&root).output() {
        Ok(output) if output.status.success() => output,
        _ => return, // packaged crate or no git: nothing to check
    };
    let tracked = String::from_utf8_lossy(&output.stdout);
    let offenders: Vec<&str> = tracked
        .split('\0')
        .filter(|p| !p.is_empty() && !is_binary_path(p))
        .filter(|p| contains_crlf(&root.join(p)))
        .collect();
    assert!(offenders.is_empty(), "tracked text files contain CRLF: {offenders:?}");
}
```

**Output shape** (`status:"ok"`):

```json

```

`verdict` is `"flag"` or `"ok"`; readiness uses `"concern"` or `"ok"`. Every asked question yields one finding, whether flagged or not, so the agent sees the probabilities. Unavailable returns `{"status":"vet_unavailable","reason":"no_key","detail":"…","readiness_gate":{…}}`.

**Question rules** (deterministic; `plan_questions`):
- Iterate failure modes sorted by `id`, then by check in `CHECKS` order.
- **observations:**
  - For each claimed id in `severity_observations ∪ probability_observations`, sorted, ask a Noul: "Given cause '<cause>' and effect '<effect>' of '<description>', does the observation '<catalog description>' apply?" The target is `<fm>/<obs>`.
  - Unclaimed: for each axis, take `catalog_for(strategy)` filtered to that axis. Find the highest `level_ordinal` among the claimed ids (or 0 if none). Pick the criterion with the lowest id at `max+1`, if one exists, and ask the same Noul. The target is `<fm>/<obs>`, and the finding records `"claimed": false`.
- **mitigations:** for each mitigation sorted by id:
  - a Score over `SCORE_LEVELS`, "How fully does '<m.description>' address the cause '<cause>'?" (target `<fm>/<m>`);
  - a Choice over criteria `prevention`/`detection`/`fail_fast`, each with a one-line definition (target `<fm>/<m>#class`).
- **coverage:** for each class in `FAILURE_CLASSES`, ask a Score over `SCORE_LEVELS`: "Does the class '<class>' plausibly apply to this analysis but is not covered by any failure mode?" These are asked once per analysis, not per failure mode, with target `coverage/<class>`.
- **readiness:** one Score over `SCORE_LEVELS`: "Is this analysis sound enough to sign off?" The target is `readiness`.
- The state sent to Jev is the subject serialised as JSON (failure modes with observations, the catalog descriptions of the claimed ids, and the mitigations).
- **Cap:**
  - the first `max_questions` planned questions are sent, in one `decide` call;
  - the rest are listed in `skipped` by hash;
  - if `max_questions` > `HARD_MAX_QUESTIONS`, the call is rejected with `invalid_params`;
  - `max_questions: 0` means nothing is sent and the result is `status:"ok"` with every question in `skipped`.

**Interpretation:**
- Noul: `p = noul`.
- Score: `p = score / 4.0`.
- Choice: `p` = the answer's probability for the declared `kind`. The finding is flagged when the argmax ≠ declared and the argmax probability ≥ 0.6; `threshold` = 0.6.
- An answer with the wrong type, or one that is missing, sends the whole call to `vet_unavailable bad_response`. This mirrors cpm-planner's decode strictness.
