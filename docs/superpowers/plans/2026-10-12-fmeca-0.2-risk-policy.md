# fmeca 0.2 — Risk Policies and Action Suggestions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks marked **[Junior]** are executed with the `junior` skill (`junior handoff`); **[Claude]** tasks by a Claude subagent with a per-task review; **[Controller]** tasks by the orchestrating session with the maintainer's go-ahead.

**Goal:** Ship fmeca 0.2.0: declarative risk policies (presets + `.fmeca/policies/*.toml`) applied at query time to an analysis, returning deterministic, tagged action suggestions and a policy-relative sign-off — without changing the kernel or the 0.1 Junior contract.

**Architecture:** A new pure crate `crates/fmeca-policy` (model, validation, confidence, evaluation, presets, rendering) depends only on `fmeca` + serde/toml/sha2. `crates/fmeca-mcp` exposes it as MCP tools `actions.suggest` and `policy.list` and CLI `suggest` / `policy validate|list`. Policies are never written to the event log.

**Tech Stack:** Rust 1.99.0 (edition 2024), serde, `toml` 1, `sha2` 0.10, rmcp 3.5; existing CI.

**Spec:** `docs/superpowers/specs/2026-10-12-fmeca-0.2-risk-policy-design.md` (binding; §2 sources, §3 policy schema, §4 evaluation, §5 surface, §6 presets).

## Global Constraints

- fmeca suggests; it never acts. No tool or command writes to the event log as a result of a policy query.
- `crates/fmeca` (kernel) is unchanged and gains no dependency; `fmeca` must not depend on `fmeca-policy`. `fmeca-policy` has no network, no clock, no filesystem access except the explicit `load_project_policy(dir, name)` reader.
- Determinism: `evaluate(analysis, policy, as_of)` is a pure function; same inputs → byte-identical JSON. Failure modes in id order; all maps ordered (`BTreeMap`).
- Confidence ladder (verbatim, spec §4.3): C0 declared only (no evidence or only `note`); C1 basis `design`, or kind `file`/`url` without basis; C2 basis `inspection`, or kind `pull_request`/`commit`; C3 basis `test` or kind `test`; C4 basis `operational_use` or `failure_history`. Best item over the mitigations that achieve the residual wins; no mitigations → C0.
- Fallback rule (MIL-STD-882E Table VI): if confidence < effective band's `min_confidence`, the effective band is the **inherent** band; output `fallback {from, to, reason}`.
- Disposition vocabulary (NPR 8000.4C): `accept, mitigate, watch, research, close, elevate`. Precedence order (MIL-STD-882E §4.3.4 adapted): `eliminate, prevent, detect, contain, procedure`.
- Default policy: `compat-0.1`; its `signoff.pass` must equal `readiness.assess.ready` on every fixture.
- Policy names: preset names or file stems in `.fmeca/policies/` matching `^[a-z0-9][a-z0-9-]{0,63}$`; anything else → `POLICY_NOT_FOUND`. Error prefixes: `POLICY_NOT_FOUND`, `INVALID_POLICY`, `POLICY_STRATEGY_MISMATCH`.
- MCP schemas: flat, no top-level `oneOf`/`anyOf`/`allOf`; `deny_unknown_fields` on inputs and on all policy TOML structs.
- Junior contract (0.1) frozen: the eight tools, binary name, six archives, `checksums.sha256`. `session.list` and `vet` unchanged.
- Tests: declarative names, one behavioural assertion each, no network. CI gates as on `dev`, plus the new purity assertion.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)` and say `Part of #<0.2 epic>`.
